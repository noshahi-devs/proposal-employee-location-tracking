Core Product Principle

1. Executive Overview

The proposed Employee Location Management System is a role-based mobile application designed to help organizations validate the current whereabouts of employees when required.

The system provides three roles: Admin, Line Manager, and Employee. The Admin manages users and employee-manager assignments. The Line Manager can view assigned employees and initiate an on-demand location validation. The Employee application provides the device's current location when the validation is triggered, subject to mobile-device permissions and platform availability.

The core MVP supports on-demand location validation. A separately approved Live Employee Tracking add-on adds driver-style real-time map tracking: a manager selects an assigned employee and watches the employee marker move as GPS updates arrive. Background tracking is intended to continue when the employee app is minimized or the phone is locked, subject to mobile OS permissions, battery policies, connectivity and device state. Historical route records remain a separate optional add-on.

2. Objectives

  • Secure role-based login for Admin, Line Manager, and Employee.
  • Manage employees and Line Manager assignments.
  • Allow Line Managers to view their assigned employees.
  • Allow an authorized Line Manager to initiate a current-location validation.
  • Retrieve current GPS coordinates only when validation is initiated.
  • Display the employee's current location on a map.
  • Show location accuracy and timestamp.
  • Prevent unauthorized managers from validating employees outside their assignment.
  • Keep continuous background tracking and historical location recording outside the core MVP unless separately approved as add-ons.
  • For the Live Employee Tracking add-on, allow a manager to select an assigned employee and view continuously refreshed GPS position on a map.
  • Support background location updates while the employee app is minimized or the screen is locked, where permitted by Android/iOS and device settings.
  • Show tracking state, last update time, GPS accuracy, signal/offline status, and an optional route trail.

4. On-Demand Employee Location Validation

The core workflow is designed around a manager validating an employee's current whereabouts. The manager does not ask the employee to manually share a location; the application initiates retrieval of the current device location.

StepProcess
1Manager opens assigned employees
2Manager selects an employee
3Manager selects “Get Current Location”
4Backend validates authorization and employee assignment
5System creates the validation request
6Employee application obtains current device GPS
7Coordinates, accuracy and timestamp are sent to backend
8Backend returns the current location
9Manager views location on map

7. Privacy / Check-In & Check-Out Business Rule

Check-in and check-out are not an attendance-management module in this project. They are included only as an optional business/privacy safeguard to determine whether an employee is currently considered active/working before allowing a location validation.

Example Privacy Rule: A Line Manager may validate the current location only when the employee is in an eligible working state, such as “Checked In.” This helps limit location retrieval to legitimate work-related situations and reduces unnecessary location access.

15. Technical Considerations

  • Location retrieval depends on device permissions, GPS availability, internet connectivity, device state and Android/iOS platform restrictions.
  • The system should not guarantee successful location retrieval in every device condition.
  • The final implementation should be tested on both Android and iOS.
  • The exact behavior when the employee application is backgrounded or closed must be validated against final mobile-platform requirements.
  • Live tracking is a separately approved add-on. The employee app should send repeated GPS updates while tracking is enabled; SignalR or an equivalent real-time channel should deliver updates to the selected manager's map without a manual refresh.
  • Background GPS should be implemented with the platform-approved Android/iOS permissions and background execution approach. The OS may throttle or stop updates due to force-stop, battery optimization, revoked permission, loss of GPS, no network, or device shutdown; uninterrupted tracking cannot be guaranteed.
  • Agree the update interval, tracking hours, employee notice/authorization, data access, and retention before implementation. A suggested starting interval is about 5–15 seconds while moving, adjusted after battery and accuracy testing.
  • The interactive HTML demo uses fictional simulated movement only. It does not access device GPS, run in the background, or send real-time data to a server.
